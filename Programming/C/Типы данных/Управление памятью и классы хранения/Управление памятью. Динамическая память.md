## Методы выделения памяти

Все программы должны резервировать пространство в памяти, достаточное для хранения данных, с которыми они работают. Всю память программы для хранения данных можно условно разделить на 3 области:

* для *статических* переменные (с внешним связыванием, внутренним связыванием, без связывания)
* для *автоматических* переменных (выделяется при входе в блок и очищается при выходе из блока  -- часто реализовано в виде стека)
* *динамически* выделяемая память (контролируется программистом, часто фрагментирована, самая медленная в работе, *куча*)

В первых двух случаях присутствует и *идентификатор*, по которому можно обратиться к указанной области памяти. В последнем выделяется анонимная область памяти и возращается адрес начала этой области.

См. [[Память пользовательской задачи. Сегменты]] и [[Programming/NASM/Структура программы|Структура программы]]

Далее подробно рассматривается *динамичекое* выделение памяти

## Динамическое выделение памяти

Подход к использованию динамической памяти в C существенно отличается от Pascal (см. [[Динамические переменные]])

В самом языке нет средств работы с динамической памятью -- они вынесены в библиотеку

Основные функции работы с динамической памятью:
* `malloc` -- выделяет память
* `free` -- освобождает память
Дополнительные функции работы с динамической памятью:
* `calloc`
* `realloc`

Заголовки функций:
```c
void *malloc(int size);
void free(boid *p);
```

Функции для работы с динамической памятью располагаются в заголовочном файле `stdlib.h`
## Функция `malloc()`

Действия функции:
* принимает в качестве параметра размер необходимой области памяти.
* выделяет такую область из "кучи"
* возвращает адрес начала выделенной области

Сама область памяти остается анонимной, без идентификатора, но возвращаемый адрес первого байта можно присвоить указателю. Возвращает нетипизированный адрес, так как не знает, для каких целей затребована память.

Пример использования на практике:
```c
double *k;
k = malloc(360*sizeof(double));
```
выделяет область памяти, достаточной для размещения `360` элементов типа `double`

При этом конфликта типов не возникает. Для наглядности можно даже *явно* приводить типы :
```c
double *ptd;
ptd = (double *)malloc(30 * sizeof(double));
```
что не требуется в C, но обязательно в C++, который не использует концепцию `void *` (то есть зависит от контекста и переносимости).

При этом указатель в обоих случаях объявлен для единичного значения типа `double`, а не на массив из N значений. Но это не мешает работать с данной областью памяти как с массивом.

Так как [[Programming/C/Типы данных/Массивы#Индексирование|Индексирование]] есть *операция над адресами*, с этой областью памяти можно работать как с массивом, обращаясь к его элементам по индексам
Пример заполнения массива с обходом элементов в цикле:
```c
for(i = 0; i < 360; i++)
	k[i] = sin((2*M_PI/360.0) * (double)i);
```

Такой метод отлично подходит для создания динамических массивов во время работы программы наряду с [[Массивы#Массивы переменной длины (C99)]] (последние имеют автоматическое время хранения):
* для более гибкого управления временем хранения лучше подойдет `malloc()` и `free()`
* для многомерных массивов читабельнее код массивов переменной длины

> [!NOTE] Функция `calloc()`
> Фактически выполняет то же самое, что и `malloc()`, только ожидает 2 аргумента:
> * количество элементов
> * размер одного элемента
> 
> Если в `malloc()` мы *вычисляем выражение* и передаем в функцию итоговое количество байт, то в `calloc()` мы *передаем* данную информацию *в виде двух аргументов*.
> 
> Еще одним отличием `calloc()` можно считать установку в значение `0` всех битов выделяемого блока.


## Функция `free`
Действия функции: 
* освобождает ранее выделенную память, делая ее вновь доступной для выделения

В качестве *параметра* принимает *адрес, ранее возвращенный функцией* `malloc`

Пример освобождения массива из предыдущего пункта:
```c
free(k);
free(ptd);
```
при этом размер области памяти указывать *не нужно* (его библиотека хранит сама)

Если функции `free()` передать что-то отличающееся от адреса, возвращенного `malloc()`, то авария практически гарантирована.

Каждый вызов `malloc()` в программме должен быть "скомпенсирован" вызовом `free()` для освобождения памяти.

Благодаря функциям `malloc()` и `free()` мы самостоятельно рассчитываем продолжительность хранения (от одного вызова до другого).
