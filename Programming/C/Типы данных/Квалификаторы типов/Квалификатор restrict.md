## Назначение квалификатора `restrict`

Данный квалификатор может быть применен только к указателям. Он сообщает компилятору, что *рассматриваемый указатель является единственным способом получить доступ к объекту данных* (первичное средство доступа к объекту данных).

Это позволяет компилятору применять некоторые дополнительные оптимизации.

Пример:
```c
int ar[10];
int * restrict restar = (int *) malloc (10 * sizeof (int));
int *par = ar;
```
Здесь:
* указатель `restar` является единственным способом получить доступ к выделенной памяти. К нему можно указать квалификатор `restrict`
* указатели `ar` и `par` оба ссылаются на одну и ту же обасть памяти. К ним нельзя применить квалификатор `restrict`.

Квалификатор `restrict` обращен и к компилятору и к програмисту:
* компилятору сообщается, что никто более не ссылается на некоторую область памяти и он волен применять оптимизации
* программист должен проследить, что указатель удовлетворяет требованиям квалификатора (никто больше не сслылается на указанную область памяти). 

Компилятор не способен отследить, выполняется ли это требование квалификатора `restrict` и ответственность (как и риск) лежит на программисте.

## Причины добавления
Данное ключевое слово было введено в стандарте C99 для того чтобы у компилятора было представление о том, можно ли применить определенные оптимизации, в том случае если указатель является единственным способом получить доступ к определенной области памяти.

Пример (надуманный):
```c
int ar[10];
int * restrict restar = (int *) malloc (10 * sizeof (int));
int *par = ar;
int n;

for (n = 0; n < 10; n++) {
	par[n] += 5;
	restar[n] += 5;
	ar[n] *=2;
	par[n] +=3;
	restar[n] += 3;
}
```
Зная, что `restar` -- единственное первичное средства доступа к блоку данных, на которые он ссылается, компилятор может заменить 2 операции на 1:
```c
restar[n] += 8;
```
В случае `par` этого сделать нельзя, так как есть еще `ar`, который также манипулирует над теми же данными что и `par`.

Без ключевого слова `restrict` компилятор всегда расчитывает на худший сценарий (кто-то еще ссылается на блок данных).

## Применение `restrict` с параметрами функций

Квалификатор `restrict` можно применять для параметров функции, которые являются указателями.

В таком случае компилятор может предположить, что внутри тела функции данные, указываемые такими параметрами, не модифицируются с помощью других идентификаторов (другие аргументы не будут обращаться к тем же областям памяти в пределах данной функции).

Пример (2 функции копирования байтов из стандартной библиотеки C):
```c
void * memcpy (void * restrict s1, const void * restrict s2, size_t n);
void * memmove(void * s1, const void * s2, size_t n);
```

* `memcpy()` требует, чтобы не было перекрытия между местоположениями. Указатели `s1` и `s2` не могут обращаться к одному и тому же блоку данных
* `memmove()` такого требования не предъявляет. При копировании данных должна соблюдать осторожность, чтобы не перезаписать данные ранее, чем скопирует их.
