Для начала необходимо дать небольшой экскурс в следующие понятия, связанные с файлами:
* текстовое и двоичное содержимое
* текстовые и двоичные файловые форматы
* текстовые и двоичные режимы файлов

## Содержимое файлов

Содержимое всех файлов хранится в двоичной форме.
* Если в файле двоичные коды символов в основном используются для представления текста -- такой файл является *текстовым*
* Если двоичные значения представляют код на машинном языке, числовые данные (во внутреннем предсавлении), кодировку изображения и т.д. -- содержимое является *двоичным*

## Файловый формат

В различных ОС могут быть разные подходы:

Ос Unix для обоих видов содержимого использует один и тот же файловый формат (так для переноса строк используется `\n` и имеется счетчик размера файла для определения конца файла).

Macintosh до выхода OS X для указания новой строки применял символ `\r`.

MS-DOS в ранних версиях для обозначения новой строки применял `\r\n`, а для признака конца файла (EOF) применял встраиваемый символ `Ctrl+Z` (там вовсе действительный файл может быть дополнен нулями, чтобы быть кратным 256).

Зоопарк полный, и его нужно как-то "обслуживать" на переносимом языке.

## Режимы работы с файлами

Язык C предлагает *два* способа представления файлов:
* текстовый режим
* двоичный режим (он же [[Блочный ввод-вывод]])

В двоичном режиме доступен *каждый байт* файла.

В текстовом режиме то, что видит программа может отличаться от того, что хранится в файле:
* при отображении и работе с содержимым будем использовать отображение как в языке C (например `\n` для переноса строк)
* при записи в файл такая скомпилированная программа будет использовать то представление, которое принято в ОС (зависит от среды компиляции, точнее от среды, под которую компилировали программу)
